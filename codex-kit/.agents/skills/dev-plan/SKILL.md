# Планирование

Прочитай `AGENTS.md`, применимые правила и `.codex/project.md`; определи цель и ограничения.
При запросе сохранить готовый согласованный план сделай это сам, без повторного исследования и агента.
Для небольшой ясной задачи составь краткий план сам. Для неизвестных зависимостей
или сложной декомпозиции делегируй `kit_planner` по
[runtime](../dev-cycle/references/runtime.md).

По умолчанию даже краткий новый план сохрани по [шаблону](references/plan-template.md)
в `.plans/YYYY-MM-DD-slug.md` в корне проекта. При необходимости создай каталог и выбери свободное имя.
При обновлении существующего плана сохрани его формат и прежний путь.
Если пользователь явно просит показать план в чате или работать без записи, верни план в ответе без создания файлов.
При делегировании укажи путь плана как область записи, для ответа в чате — `Write scope: none`.
Автор файла сам запускает `plans.py` по [жизненному циклу](references/lifecycle.md).
Для сохранённого плана верни путь, итог проверки и следующий шаг. При передаче переиспользуй проверку той же версии.
Планирование не запускает реализацию.
Если план сохранён/изменён, основная сессия оформляет внутреннюю запись по
`.codex/rules/history.md`: описывай планирование, не объявляй фичу реализованной.

## Проверка простоты

Автор нового плана сам делает один проход перед ответом или переводом в `ready`.
При изменении объёма проверь только затронутую оставшуюся работу. При передаче между
агентами используй результат автора. При сохранении согласованного плана сохрани его содержание.

- Начни с кратчайшего решения на существующих компонентах. Для нового сервиса, слоя,
  инструмента или миграции укажи, какое требование или ограничение требует этого шага.
  Убери задел на будущее, если задачу можно принять без него.
- Оставь отдельную задачу, когда у неё есть самостоятельно проверяемый результат
  или она открывает зависимую работу. Объедини правки одного поведения и их проверки.
  Например, исправление двойной отправки и регрессионный тест обычно образуют одну задачу.
- После сокращения сверь исходные критерии и существенные риски. Сохрани порядок совместимого
  развёртывания, проверки прав, бюджета и восстановления там, где от них зависит приёмка.
  Передай итоговый план. Отдельный отчёт об упрощении и повторный запуск планировщика не требуются.
