## Сценарии независимой проверки процесса

1. Локальная опечатка без изменения поведения: минимальный путь.
2. Изменение семантики API с тестами: реализация и независимое ревью.
3. Миграция данных в нескольких строках: размер не снижает требования к проверке.
4. Backend и frontend с общим контрактом и lockfile: безопасное распределение записи.
5. Повторяющееся замечание ревью: ограниченный цикл, смена подхода.
6. Запрос только на план: без самовольного перехода к реализации.
7. Недоступная назначенная модель: без молчаливой подмены и ложного отчёта.

Это проверка принятия решений по инструкциям, не сравнительный бенчмарк моделей.
Нативная загрузка ролей в новом целевом проекте и выполнение реальных проектных
тестов требуют проверки в соответствующем клиенте/репозитории.
