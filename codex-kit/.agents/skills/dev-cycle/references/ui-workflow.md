# Выбор UI-ролей

Это условная часть dev-cycle; запуск — по [runtime](runtime.md), профили — в TOML ролей.
Не вводи ещё один полный цикл, отдельного Git-агента или reviewer на каждый экран.

- Малая безопасная правка текста/стиля без изменения поведения — основная сессия.
  Локальный UI-баг с готовым решением — основная сессия либо `kit_ui_developer`,
  с обязательным независимым ревью поведения. Дизайнер не нужен.
  Значимую реализацию UI поручай `kit_ui_developer`, заменяя общего developer в этой области.
- Для сценария/композиции/стиля без достаточного дизайна или паттерна сначала нужен
  `kit_ui_designer`. При готовом достаточном решении пропускай его, включая новый экран.
  Только концепция/дизайн по запросу — только дизайнер, без перехода к реализации.
- Передай дизайнеру цель, пользователей, платформу, ограничения и существующие образцы.
  Выход по его роли — одна спецификация в ответе/плане либо выделенный прототип.
  Read-only/«только словами» не требуют файла/рендера. Planner отвечает только за общие
  зависимости: не запускай его ради повторного описания экранов, а дизайнера — ради готового плана.
- Оркестратор передаёт UI-разработчику конкретное дизайн-решение/артефакт и контракт API.
  Backend может выполнять `kit_developer` в независимой области после фиксации контракта.
  Общие файлы и ресурсы подчиняются владению/лимиту dev-cycle. Не меняй макет под исполнителем.
- До общего ревью автор проверяет UI по [ux-ui](../../../../.codex/rules/ux-ui.md) и
  [client](../../../../.codex/rules/client.md), прикладывает доступные визуальные свидетельства
  и результаты поведенческих проверок. Значимые UI-изменения проверяет `kit_reviewer`;
  дизайнер/разработчик не заменяет независимую проверку своей работы.
  Нужные уточнения возвращаются той же роли адресно. Недоступный рендер не считается пройденным.
- План, история, критерии завершения и интеграционные проверки остаются в dev-cycle.
  Сохранённая концепция записывается как проектирование, не как реализованная функция.
- При недоступном делегировании основная сессия может подготовить концепцию по тем же
  критериям, указав ограничение. Это не запуск профиля и не замена независимого ревью реализации.
