# Модели и effort

Стартовый профиль, а не доказанный глобальный оптимум. Модели и уровни проверены
по инструментам этой сессии и локальному кешу 2026-11-14. Стоимость конкретных
моделей/подписки здесь не рассчитывается; сравнивать её нужно по фактической телеметрии.

| Роль | Модель | Effort | Зачем такой профиль |
|---|---|---|---|
| `kit_explorer` | `gpt-6-luna` | `medium` | Узкий поиск фактов и путей без проектирования |
| `kit_planner` | `gpt-6.1-sol` | `medium` | Декомпозиция и зависимости, без обязательного высокого effort |
| `kit_developer` | `gpt-6.1-terra` | `medium` | Стартовый кандидат для реализации и проверок кода |
| `kit_ui_designer` | `gpt-6.1-sol` | `medium` | Сценарии, композиция и согласованный визуальный язык |
| `kit_ui_developer` | `gpt-6.1-terra` | `medium` | Реализация web/desktop UI, поведение и рендер |
| `kit_reviewer` | `gpt-6.1-sol` | `high` | Независимый анализ граничных случаев и взаимодействий |
| `kit_documenter` | `gpt-6-luna` | `medium` | Документы из ограниченного набора проверенных фактов |
| `kit_expert` | `gpt-6-astra` | `high` | Только сложный вопрос, который не решён обычным циклом |

UI-роли добавлены 2026-11-15. Их модель/effort явно заданы и проверены по локальному
кешу; это стартовые кандидаты, не результат сравнительного UX-бенчмарка. Дизайнер
подключается при неизвестном сценарии/композиции/стиле. UI-разработчик заменяет общего
developer в выделенной UI-области; остальные роли и общий лимит параллелизма сохраняются.

«Своя модель» означает явный профиль на роль; разные роли могут использовать одну
модель. Уникальная модель для каждого имени сама по себе не улучшает результат.
Разные developer/reviewer полезны как эксперимент, но независимый scope и отсутствие
подсказки желаемого вывода важнее различия названий моделей.

Для основной сессии предлагается `gpt-6.1-sol / medium`, если доступна. Комплект
не меняет глобальную настройку пользователя (`gpt-6-astra / high` на момент проверки).

## Как менять

Редактируй `model` и `model_reasoning_effort` только в нужном
`.codex/agents/kit_*.toml`. Не создавай отдельную таблицу настроек в skill:
адаптер читает этот же TOML. Оба поля обязательны, чтобы не получить непреднамеренное
наследование effort основной сессии.

Если developer стабильно справляется с типовыми задачами — сравни `medium` с `low`
на одинаковом наборе задач. Если повторяются ошибки анализа — сначала проверь
scope, критерии и тесты, затем увеличь effort на один уровень. Для архитектурной
неопределённости полезнее адресный expert, чем перевод всех ролей на high/max.
Смена модели в конкретном запуске должна быть явной и отмеченной в отчёте.

Не используй автоматический fallback на более дорогую модель при недоступности:
он скрывает расход. Выполни допустимую часть основной сессией, укажи ограничение.

## Совместимость

Официальная документация описывает TOML-профили и выбор модели/effort.
В этом чате инструмент `collaboration.spawn_agent` принимает явные параметры
`model`, `reasoning_effort`, `fork_turns`, но не имя зарегистрированной роли.
Поэтому предусмотрены два маршрута запуска; не нужно выдумывать `agent_type`
в интерфейсе, где его нет. Файлы роли не задают отдельные разрешения на запись.
