# Модели и effort

Профили от 18 ноября 2026 года сверены с каталогом Codex на этой машине и с параметрами явного запуска субагентов в этой сессии. Для переноса в другой проект источником настроек служат файлы в `codex-kit/.codex/agents/`.

| Роль | Модель | Effort | Задача |
|---|---|---|---|
| `kit_explorer` | `gpt-6.2-sol` | `low` | Найти точку входа, владельца кода и команду проверки |
| `kit_documenter` | `gpt-6.2-sol` | `low` | Подготовить инструкцию по уже проверенным фактам |
| `kit_planner` | `gpt-6.2-sol` | `medium` | Разложить неоднозначную задачу, установить зависимости и критерии |
| `kit_developer` | `gpt-6.2-sol` | `medium` | Реализовать и проверить изменение общего кода |
| `kit_ui_designer` | `gpt-6.1-terra` | `medium` | Спроектировать сценарий и состояния с учётом визуальных материалов |
| `kit_ui_developer` | `gpt-6.1-terra` | `medium` | Реализовать интерфейс и проверить его на целевой платформе |
| `kit_reviewer` | `gpt-6.2-sol` | `high` | Независимо проверить изменение и взаимодействие компонентов |
| `kit_expert` | `gpt-6.2-astra` | `high` | Разобрать конкретную причину, которую не удалось установить за два раунда |

Для короткого поиска и документации выбран низкий effort. Для UI выбрана Terra с учётом её визуальной специализации. Отдельный контекст и собственная проверка ревьюера обеспечивают независимость от автора, даже когда они используют одну модель. Модель основной сессии выбирает владелец проекта.

## Настройка и проверка

Меняй `model` и `model_reasoning_effort` в TOML нужной роли. При переносе сверь допустимые значения в целевом клиенте, затем запусти одну роль на реальной задаче. Порядок загрузки проектных TOML описан в [документации Codex](https://learn.chatgpt.com/docs/agent-configuration/subagents). [Проверка после переноса](quick-start.md#4-проверить-в-codex).

До изменения профиля сравни два варианта на одинаковых задачах с одной базой, критериями и инструментами. Оцени долю принятых результатов с первого прохода, пропущенные дефекты, число возвратов, время и суммарные токены всех участников на принятый результат, если клиент их показывает. Для UI включи проверку отрисованного сценария. Меньший effort сам по себе экономию не доказывает.
