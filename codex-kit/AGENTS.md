# Работа с проектом

Сначала прочитай `.codex/project.md` и применимые вложенные `AGENTS.md`.
Пути и команды проверяй относительно целевого репозитория, а не исходного комплекта.

## Правила по области изменения

Читай подходящие строки таблицы по затронутым эффектам и границам, не только по файлам.
Выбор накопительный: при обнаружении нового влияния дочитай правила даже без расширения записи.
Это обычные ссылки для агента, не автоматически загружаемый механизм `.codex/rules`.
В задании субагенту укажи выбранные правила и особые проектные инварианты.
Уже прочитанное в текущем контексте не перечитывай без изменения файла/задачи.
Ссылки открывай по их условию, не рекурсивно. Полные руководства и исходники служебных
скриптов нужны при настройке/исправлении, для обычного запуска достаточно команды.

Применяй правила к затронутой области, не создавай задачу на переустройство проекта.
Git-состоянием каждого worktree управляет один владелец: по умолчанию основная сессия.
Субагент получает готовый baseline; Git-владение передаётся только явно по workflow.
Очереди, outbox, Kubernetes, tracing и отдельные сервисы не обязательны сами по себе.
При отличии проектной политики зафиксируй применимое решение; не скрывай противоречие.

Основная сессия выбирает процесс; субагент выполняет назначенную роль, не запускает
этот цикл заново и не ведёт общие план/историю без назначения владельцем:
- Простая локальная правка без изменения поведения и с низким риском: выполни сам,
  без плана и субагентов, с подходящей проверкой.
- Изменение поведения или высокий риск, даже в одну строку: `dev-cycle` и независимое ревью.
- Многошаговая реализация или выполнение плана: `.agents/skills/dev-cycle/SKILL.md`.
- Только планирование, ревью или документация: соответствующий `dev-plan`, `dev-review`, `dev-docs`.
- Проектирование или значимое изменение UI, включая реализацию готового дизайна:
  [условный маршрут UI-ролей](.agents/skills/dev-cycle/references/ui-workflow.md).
- Вопрос или исследование не означает разрешения менять код.

В этих навыках разрешено делегировать по описанным критериям. У каждого субагента
свои модель и effort из `.codex/agents/`; не наследуй дорогую модель автоматически.
Субагенты не делегируют дальше. Читай только выбранную роль и нужные ссылки.
Передавай короткое самостоятельное задание вместо истории чата.

Не отменяй чужие изменения. Изменения, проверки и недоступные проверки отражай явно.
Перед завершением любого изменения основная сессия создаёт/проверяет отдельную запись
в `.changes/entries/`; при делегировании назначает одного владельца, без дублирования.
Сборка производного журнала и добавление самой записи не требуют рекурсивных записей.
Коммит, push, публикация и изменение внешних систем — только в разрешённом пользователем объёме.
