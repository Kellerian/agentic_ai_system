# Работа с Git

Соблюдай владельца и разрешения из `AGENTS.md`; навык не разрешает сам по себе коммит,
публикацию или переписывание истории. Выполняй только нужные пункты, без нового dev-cycle.

- Перед правками или операцией, меняющей Git-состояние, проверь корень/worktree,
  ветку/HEAD (либо отсутствие первого коммита),
  status и незавершённые merge/rebase/cherry-pick. Чужую операцию не продолжай/отменяй
  без задания. Зафиксируй HEAD/status; для затронутых грязных файлов — отдельно staged/
  unstaged diff и исходное содержимое untracked в разрешённом временном месте.
  Без Git используй снимки файлов, не создавай репозиторий автоматически.
  Не очищай дерево reset/stash/checkout ради удобства. Итог сверяй с baseline,
  сохраняя чужие правки, включая staged-состояние.
  Для commit-only также зафиксируй исходный чужой staged diff для последующей сверки.
- Оркестратор явно передаёт Git-владение: worktree, действия и момент возврата.
  Другие исполнители меняют только назначенные файлы и читают diff/status, но не индекс/
  ветку/историю. Read-only и параллельный status: `git --no-optional-locks status`.
  Перед Git-операцией, меняющей индекс/дерево, останови конкурирующую запись исполнителей,
  получи подтверждение от них и перечитай состояние.
- Перед изменением индекса, операциями с worktree/refs, fetch/push, merge/rebase/cherry-pick или commit
  прочитай [операционные шаги](references/operations.md). Для обычного baseline,
  чтения diff и правки файлов этот материал не нужен.
- При фактической Git-операции сообщи результат, HEAD и остаточный status.
  Нумерация версий и именование веток остаются политикой проекта.
