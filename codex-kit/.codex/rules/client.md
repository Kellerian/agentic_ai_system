# Web и desktop клиент

Применяется к UI, состоянию клиента и взаимодействию с сервером/устройствами.

- Не блокируй UI thread/event loop I/O, тяжёлыми вычислениями или синхронным ожиданием
  фоновой задачи. Используй неблокирующий I/O и подходящий worker/thread/process:
  само async не переносит вычисления. UI обновляется механизмом его фреймворка/потока;
  обработчики остаются короткими, большие результаты/списки обрабатываются порциями.
- Длительная операция пользователя или ожидание, задерживающее его сценарий, имеет
  видимый статус: что происходит и чего ждать. Принятие действия подтверждается сразу;
  индикатор должен отрисовываться и обновляться во время работы. Известен объём —
  фактический прогресс/этапы; неизвестен — ожидание с текстом, без выдуманных процентов/ETA.
  Задержка индикатора против мигания допустима по проекту, длительная работа видна всегда.
- Индикатор ставь у занятой области. Сплэш/модальность нужны, когда без результата
  нельзя продолжить сценарий. Блокируй только конфликтующие действия; перерисовка
  и разрешённый ввод остаются доступны. Служебный фон не требует постоянного сплэша.
- Различай выполнение, успех, отказ, отмену, неизвестный результат; для чтения также
  пустые данные, отсутствие прав, offline и устарелость. Сбой — не пустой успешный список.
  Во всех терминальных ветках снимай busy, не снимая его с другой текущей операции.
  Анимация не доказывает работу сервера: за бюджетом ожидания показывай задержку/сбой
  и следующий шаг. Для долгого задания используй контракт статуса вместо бесконечного запроса.
- Предлагай безопасную поддерживаемую отмену; прекращение ожидания не отменяет
  серверный эффект. Неизвестный результат сверяй, не повторяй команду автоматически.
  При уходе с экрана закрывай подписки/таймеры/ресурсы, отменяй ненужную работу где
  возможно, не обновляй уничтоженный экран.
- Поздний ответ старого запроса/сессии не перезаписывает новое состояние, в том числе
  после logout. Cache/query ключи учитывают параметры и пользователя/tenant;
  смена сессии очищает чувствительные данные.
- Повторный клик/reconnect не дублирует бизнес-эффект. Disabled-кнопка — UX;
  защиту на сервере задаёт [безопасный повтор](distributed.md). Offline-очередь добавляй
  только с правилами хранения, синхронизации, конфликтов и индикации.
- Optimistic UI требует компенсации/сверки. Для физических/денежных операций
  показывай подтверждённый результат, не локальное предположение.
- Соблюдай доступность: клавиатура, focus, подписи, ошибки и объявление статуса,
  не только цвет/анимация. Формат дат/чисел отделяй от транспорта и единиц измерения.
- Проверь затронутый сценарий. При влиянии на ожидание/асинхронную или тяжёлую работу
  используй медленный ответ: UI/индикатор отзывчивы, повтор безопасен; по влиянию проверь
  ошибку/таймаут, отмену, уход с экрана, гонку ответов и очистку busy. Чистую визуальную
  правку проверь рендером и затронутым взаимодействием, без незатронутых сетевых сценариев.
  Недоступность проверки укажи. Скриншот не проверяет поведение.
