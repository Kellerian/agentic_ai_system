# Записи изменений

Каждый законченный логический результат получает отдельную запись в `.changes/entries/`
в той же ветке. Это обязательно с планом и без него, включая docs, тесты, конфигурацию
и сохранение плана. Read-only работа, сама запись и генерация сводки новых записей не требуют.

- Владелец — основная сессия или один явно назначенный агент. Не создавай запись на
  каждый файл/коммит/раунд ревью. Независимые результаты имеют отдельные записи;
  закрытие плана в том же изменении не дублирует их. Если отдельный PR/изменение
  только обновляет уже реализованный план, нужна короткая внутренняя запись об этом,
  со ссылками на прежние результаты; не объявляй фичу реализованной повторно.
- Подготовь текст после проверок и включи в уже необходимое ревью реализации.
  После PASS сохрани проверенный текст; изменение смысла требует целевого follow-up.
  Малый прямой путь проверяет автор, без агента только ради истории.
- `user` — видимый результат для пользователя; `support` — условия, решение,
  подтверждённые проверки/ограничения. Без пользовательского эффекта укажи
  `internal_reason` вместо `user`. Планирование описывай как планирование.
  `references` связывает план/задачу; секреты и персональные данные исключены.
- Создай запись: `python .codex/scripts/changes.py new --kind <тип> --component <область>
  --support <текст> --user <текст>`; для внутренней — `--internal-reason` вместо `--user`.
  Несовместимость требует `--breaking` и `--action-required`. UUID и UTC создаёт скрипт.
  Допустимые типы/параметры: `new --help`; схема, CI и сборка — в
  [руководстве](../../.changes/README.md), читать при настройке/неясности формата.
- До слияния уточняй свою запись; при полной отмене убери непринятое описание.
  После принятия история неизменяема: исправление/отмена — новая запись со ссылкой
  на старый ID. Backport сохраняет исходный ID. Общие changelog генерируются сборкой;
  не редактируй их вручную и не удаляй исходные записи после выпуска.
- Перед завершением выполни `python .codex/scripts/changes.py check`, укажи путь записи.
  Невозможность записи/проверки — открытый критерий оформления, не скрывай её.
