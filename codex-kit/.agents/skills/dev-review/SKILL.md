# Ревью

Прочитай `AGENTS.md` и применимые правила; включи их в область проверки.
Явные diff, пути или refs в запросе определяют scope. Только если scope не указан,
используй текущие незакоммиченные изменения, включая staged и новые файлы.
Для read-only статуса используй `git --no-optional-locks status`. Для ветки используй
проверенную базу и merge-base; не подставляй main наугад и не переключай ветку
только ради просмотра. Если цель неоднозначна, уточни scope.

Чужой diff основная сессия может проверить сама по критериям
`.codex/agents/kit_reviewer.toml`; её модель/effort от чтения TOML не меняются.
Если участвовал в реализации или нужен отдельный взгляд по риску/запросу, делегируй
одному `kit_reviewer` по [runtime](../dev-cycle/references/runtime.md), передав
baseline, требования, пути и проверки. Собственную реализацию не объявляй независимо
проверенной при недоступности делегирования. Обязательное ревью в dev-cycle сохраняется.
Не меняй код и не запускай исправления без соответствующего запроса.
Верни findings с условиями и последствиями либо границы проверки без находок.
