# Git-операции по необходимости

Владение и baseline задаёт [git-workflow](../SKILL.md). Выполняй только разрешённое заданием.

## Worktree и общие refs

Для независимых веток worktree допустим по необходимости в разрешённой области.
HEAD/индексы отдельны, refs и часть состояния общие: их изменение, fetch/push и управление
worktree координирует один владелец на репозиторий. БД/порты/внешние ресурсы этим не изолируются.
Перед удалением проверь незакоммиченные/untracked файлы и неперенесённые коммиты;
force не применяется для автоматической уборки.

## Интеграция

Зафиксируй source/target refs и коммиты, проверь базу, не угадывай main/remote.
Merge/rebase/cherry-pick выбирай по процессу проекта. Смысловой конфликт решается
по контракту и обеим реализациям, не механическим ours/theirs. Всегда осмотри объединённый
результат; проверь затронутые границы интеграции по риску, даже при отсутствии конфликтов.
Прежний PASS применим только в проверенных пределах. Новое решение или ранее не проверенное
взаимодействие требует адресных проверок и независимого ревью по dev-cycle; смена SHA
сама по себе не повод повторять весь цикл. Новое поведение следует TDD по инженерным правилам.
Перенос существующей записи сохраняет ID; новый самостоятельный результат оформляется
по [истории](../../../../.codex/rules/history.md).

## Коммит и публикация

В разрешённый коммит включай только относящиеся к задаче пути/фрагменты, без безусловного
add -A. До commit проверь точный diff будущего коммита относительно HEAD (для первого —
весь состав). Staged diff не описывает иной индекс или commit с pathspec, способный
включить чужие unstaged-фрагменты целого файла. После commit сверь фактический diff и
сохранность чужого staged с baseline. Если разделение нельзя гарантировать, используй
разрешённый worktree либо согласуй состав, не сбрасывая чужой индекс и не меняя целевую ветку.

Оформление точно того же проверенного содержимого с той же базой/условиями сохраняет
подтверждённые проверки, PASS и запись. Новые тесты, агенты и запись только ради коммита
не нужны. Если hooks/форматирование изменили содержимое или условия проверки изменились,
оцени delta и выполни необходимые проверки/адресное ревью до объявления результата
проверенным и до публикации.

Перед разрешённым push проверь remote, ветку и отправляемые коммиты. Force-push,
потеря локальных данных и переписывание опубликованной истории не входят в обычное оформление.
