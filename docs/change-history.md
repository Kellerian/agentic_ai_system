# Единая история без общего редактируемого changelog

Идея рациональна: несколько веток добавляют разные файлы, а сводку формирует сборка.
Такой подход называют news fragments; например, [Towncrier](https://towncrier.readthedocs.io/en/stable/)
использует отдельные описания изменений вместо конкурентного редактирования общего журнала.
Это снижает конфликты текстового файла, но не устраняет смысловые дубли или конфликты кода.

## Принятое решение

```text
Завершённый результат (с планом или без)
  → отдельный .changes/entries/YYYY/<время UTC>_<UUID>.json
  → проверка содержания и формата
  → commit/PR вместе с кодом
  → сборка из конкретного Git-коммита относительно предыдущего выпуска
      → CHANGELOG.md для пользователей
      → SUPPORT-CHANGELOG.md для поддержки
      → manifest.json с составом и хешами
```

Для комплекта сделан небольшой автономный Python-скрипт без дополнительных библиотек.
Причины: перенос копированием, две аудитории в одной записи, отсутствие собственной
политики версионирования и неизменяемая история. Если в целевом проекте уже используется
Towncrier или аналогичный механизм, лучше интегрировать эти правила в него, чем вести
две параллельные истории. Схема данных и правила полезны независимо от реализации.

## Почему именно так

- **Один результат, не один коммит.** Внутренние итерации разработки не интересны
  пользователю. План с несколькими самостоятельными результатами даёт несколько записей;
  закрытие плана в том же изменении не дублирует их. Самостоятельная правка уже
  выполненного плана получает внутреннюю запись об этой правке. Небольшая правка
  без плана тоже записывается.
- **Все изменения учтены, пользовательские заметки отфильтрованы.** Для тестов,
  рефакторинга, планирования и косметики возможна внутренняя запись с объяснением.
  Она видна поддержке, но не засоряет пользовательскую сводку.
- **Два текста, одна идентичность.** Пользователь получает поведение и эффект;
  поддержка — условия, исправление, проверки и ссылки. Сборщик не пытается вывести
  человеческое описание из Git diff или технического сообщения коммита.
- **UTC + UUID.** Имя читаемо и практически уникально при параллельной работе.
  Эксклюзивная публикация защищает от перезаписи при коллизии. Время не определяет
  состав релиза: оно могло быть записано задолго до merge.
- **Git-снимки вместо календарного фильтра.** Сравнение ID между base/head учитывает
  долгоживущую ветку и backport. База выбирается для конкретной линии поддержки.
- **Нет shared index / released flags.** Сборка не меняет записи и не создаёт общий
  файл состояния в рабочих ветках. Повторный запуск с теми же входами воспроизводим.
- **Версия извне.** Сборщик получает название/номер и дату выпуска от существующего
  build script. Не вычисляет semver, префиксы или номера сборок.

## Где нужна дисциплина

В техническом тексте нельзя объявлять исправленную ошибку без проверки; в пользовательском
нельзя перечислять только классы и внутренние файлы. ИИ помогает написать запись сразу
после изменения, но ревью должно сверять её с реальным поведением. Черновик текста
передаётся на уже запланированное ревью кода — дополнительный агент обычно не нужен.

CI-команда `check --require-entry` обнаруживает отсутствие хотя бы одной новой записи
при изменении файлов. Она не доказывает, что одна запись покрыла все пять улучшений
или что внутренний эффект правильно классифицирован. Это остаётся частью критериев готовности.

После принятия записи её не удаляют и не переписывают: отмена и уточнение — новые записи
с ссылками. До merge собственный черновик можно исправить или убрать вместе с полностью
отменённой правкой. Если изменение сначала добавили, затем отменили до выпуска, автоматическая
сводка может содержать оба события; редакторская проверка итогового текста необходима.

В пользовательский дистрибутив по умолчанию идёт только `CHANGELOG.md`. Технический отчёт
и manifest сохраняются для поддержки/CI. Нельзя автоматически упаковывать весь каталог
вывода, предполагая, что внутренние ссылки и подробности предназначены пользователю.
Секретам и персональным данным нет места ни в одном варианте истории.
