# Запуск ролей Codex

Единственный источник модели, effort и инструкций роли — `.codex/agents/kit_<role>.toml`.
Читай только выбранный файл. Все пути в задании делай однозначными относительно
целевого репозитория. Новому агенту передай также путь его `AGENTS.md` и `.codex/project.md`.

## Выбор интерфейса

Проверь фактическую схему доступного инструмента:

1. Если поддержан выбор зарегистрированной роли (`agent_type` или эквивалент),
   проверь, что нужная роль доступна текущему клиенту, и выбирай `name` из TOML.
   Не дублируй её инструкции в задании. Файлы зарегистрированы в `.codex/config.toml`;
   наличие параметра роли не доказывает загрузку регистрации. Если роль не найдена
   или её конфигурация не применяется, перейди к явному маршруту 2, когда он доступен.
2. Если доступен `collaboration.spawn_agent` с `model`, `reasoning_effort`, `fork_turns`,
   передай модель из `model`, effort из `model_reasoning_effort`, `fork_turns: "none"`.
   В `message` передай `developer_instructions` выбранного TOML и самостоятельное задание.
   Не используй наследование всей истории для экономии контекста и смены модели.
3. Если ни зарегистрированный, ни явный маршрут недоступны, не заявляй, что профиль применён.
   Для реализации работай в основной сессии, если это разумно. Если обязательное
   независимое ревью невозможно, укажи ограничение и не объявляй его пройденным.
   Не запускай вложенный `codex exec` как обход ограничений текущих инструментов.

Используй только параметры реального API. В fallback поле TOML `model_reasoning_effort`
становится аргументом `reasoning_effort`; `name` роли — это НЕ аргумент API.
У `task_name` — уникальное имя латиницей, цифрами и подчёркиваниями.
Если назначенная модель недоступна, сообщи это; не заменяй её молча дорогой моделью.
Работу, которую можно корректно выполнить основной сессией, продолжай.

## Задание

```text
Repository: <absolute path>
Task: <проверяемый результат>
Write scope: <точные файлы/модули либо none>
Acceptance: <критерии>
Context: <только необходимые решения/факты и ссылки>
Rules: <пути применимых правил из AGENTS.md; дочитать при расширении scope>
Baseline: <ревизия; исходный diff/снимки, если применимо>
Checks: <известные команды и ограничения>
Output: <какой результат нужен>
```

Scope — инструкция, не отдельная песочница. Ничего не обещай о технической
изоляции прав записи. Субагенты наследуют разрешения среды и не делегируют дальше.
После запуска дождись результата; для продолжения той же задачи используй follow-up.
Follow-up не означает смену модели/effort: продолжай им ту же роль и профиль.
Если слоты заняты, дождись/закрой завершённых агентов, когда API это поддерживает;
иначе используй доступные слоты/агентов последовательно, не создавай бесконечную очередь.
Не переназначай разработчика независимым ревьюером его собственной работы.
Повтори неудачный технический запуск только после исправления причины, не более одного раза.
Не путай ошибку запуска с замечаниями к коду. Не заверши запрос с работающими агентами.

По умолчанию соблюдай профиль роли. Для существенно более сложной задачи можно
увеличить effort на один поддерживаемый уровень при явной передаче параметров;
зафиксируй изменение. Не включай max/ultra и дополнительные роли автоматически.
Для трудного неразрешённого вопроса предусмотрен `kit_expert`.
