# Данные, транзакции и миграции

Применяется к БД, кэшам и общему изменяемому состоянию; не задаёт нумерацию миграций.

- Для каждого изменяемого набора данных известен владелец и инварианты. В отдельных
  сервисах не обходи владельца прямой записью в его таблицы; в legacy-общей БД
  сохрани совместимость и обозначь связь, не запускай переписывание архитектуры.
- Параметризуй запросы. Целостность и уникальность обеспечивай ограничениями БД,
  где возможно; проверка «найти, затем вставить» без защиты не исключает гонку.
- Определи границу транзакции, блокировки/изоляцию и конфликт конкурентных изменений.
  Не удерживай транзакцию на время сети/пользовательского ожидания без необходимости.
  Повтор после deadlock/serialization failure повторяет всю допустимую транзакцию
  и не дублирует уже выполненный внешний эффект.
- Изменение физической схемы сопровождается миграцией в существующем инструменте.
  Правка ORM без изменения схемы сама по себе не требует пустой миграции.
  Autogenerate проверяй вручную: ограничения, индексы, defaults, SQL-объекты, потери данных.
- Для работающих клиентов и смешанного развёртывания разделяй добавление схемы,
  переход кода/перенос данных и удаление старого. Не удаляй поле, пока его использует
  поддерживаемый потребитель. Не вводи Alembic/PostgreSQL, если проект использует другое.
- Оцени блокировки, длительность и объём данных. Большой backfill делай ограниченными
  порциями с возобновлением и проверкой результата. Миграция не должна гоняться
  несколькими экземплярами приложения одновременно без координации.
- Проверяй переход со старого состояния и развёртывание с нуля в изолированной БД.
  Для опасного изменения опиши восстановление. Не обещай безопасный downgrade,
  если информация уничтожена: нужен проверенный backup/restore или путь исправления вперёд.
- Для затронутых запросов проверь bounded выборку, N+1, индексы и план на характерном
  объёме по риску. Стратегия кэша определяет источник истины, инвалидирование,
  TTL и допустимую устарелость; ключи разделяют пользователей/тенанты.
- Проверки миграций и восстановления не запускаются на production-данных без
  соответствующего разрешения. Не включай реальные секреты/дампы в тестовые fixtures.
